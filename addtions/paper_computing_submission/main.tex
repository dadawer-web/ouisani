\begin{abstract}
Multi-tenant agent runtimes share executors, admission controls, and
permission services. We study a conditional dependability failure in which
resource pressure delays a permission decision and a permissive deadline
fallback turns that availability loss into unsafe admission. We present
Neuron, a Java runtime architecture that reserves permission capacity and
feeds a resource-pressure signal into the escalation policy. Identity
propagation, privilege non-increase, and correlated auditing support the
architecture but are not separate contributions. We evaluate production
Java~21 token-bucket and escalation-policy code against four predeclared
architectures: shared fail-open, shared fail-closed, isolated without
coupling, and coupled governance. Five independent JVM runs on each of a
Windows host and an Ubuntu~22.04 one-vCPU KVM VPS cover 71,880 observations
across deadline, attacker-pressure, and capacity sweeps. We additionally
replay 33 API-derived sessions (254 immutable tool calls), exercise a
process-separated Java permission service over same-host loopback with
injected delay, queue pressure, and pauses (3,200 observations), and run a
post-selection holdout of 180 observations from six new workload profiles.
Reserved capacity and fail-closed handling preserve safety under policy
starvation, while coupling changes the depth-1 decision when pressure exceeds
the fixed threshold of 50. The holdout detects 90/90 attack observations with
0/90 false positives. The loopback service experiment is not evidence about
WAN or multi-node deployments.
\end{abstract}
