\section{RQ1: Prevalence of Recovery-Path Provenance Gaps}
\label{sec:results}

This section addresses RQ1: \emph{How prevalent is the trust-escalation trampoline signature across production-grade self-healing LLM agent frameworks?} We answer this question in two steps. First, we present the recovery-path provenance taxonomy derived from grounded-theory coding of all six frameworks (\S\ref{sec:rq1-taxonomy}). Second, we apply the trampoline judgment criteria (Q1: provenance tag; Q2: high-trust frame) to each framework and report the cross-case classification (\S\ref{sec:rq1-trampoline}). The exploitability of the identified signature is examined separately in RQ2 (\S\ref{sec:severity}).

\paragraph{No-provenance pattern (5/6 frameworks).}
Five of the six frameworks do not distinguish internally generated diagnostic content from externally originated content in the failure payload. The structural commonality across these codebases is striking: in every case, the failure payload is stored and propagated as an opaque string whose origin is discarded at the capture site.

In Reflexion, the \code{feedback} string---which may embed arbitrary text printed by an adversarial test case---is concatenated verbatim into the retry prompt (Listing~\ref{lst:wild-reflexion}). The string is assembled by a Python f-string that interleaves the few-shot example, the previous implementation, the raw test-runner output, and the reflection note, with no field marking which portion originated externally.

In MetaGPT, test \code{stderr} is injected as ``Console logs'' under a role-playing frame with no provenance tag (Listing~\ref{lst:wild-metagpt}). The prompt template instructs the LLM to ``figure out your own role'' from the message, treating the entire payload---including the stderr---as authoritative context to act upon.

In Aider, the target file content (which may be an adversarial file the agent was asked to edit) is embedded in a \code{ValueError} message that is re-injected into the next LLM iteration via the \code{num\_reflections} loop. The framework's edit-instruction frame (``Just reply with fixed versions'') and the file content are concatenated with no delimiter that would allow the LLM to distinguish framework directives from external content.

In AutoGen, tool exceptions are formatted as \code{"Error: \{e\}"} and returned in the same \code{tool} role used for successful results. Although a boolean \code{is\_exec\_success} signal is computed at the tool-execution site, it is discarded at all five call sites we inspected, so the error content enters the conversation history with no provenance tag and no role distinction from legitimate output.

In OpenHands, \code{ErrorObservation} objects are appended to \code{state.history} and converted to LLM messages via the same \code{conversation\_memory.process\_events} path as successful observations. The error status is recorded in the object's metadata but is not reflected in the message-level trust framing that the LLM receives.

\paragraph{Partial-provenance pattern (1/6 frameworks).}
LangGraph is the only framework that provides partial provenance tagging. Its prebuilt \code{ToolNode} can wrap tool \emph{exceptions} in a \code{ToolMessage} with \code{status="error"} metadata when \code{handle\_tool\_errors} is enabled. However, when a tool \emph{returns} an error-like string (the common case for tools that fetch external content and encounter a processing error), the \code{ToolMessage} status is \code{"success"}---there is no content-level trust framing to distinguish error-recovery content from legitimate output. No framework in our sample achieves full-provenance tracking.

\paragraph{Cross-case convergence.}
The prevalence of the no-provenance pattern (5/6 frameworks) indicates that the absence of provenance tracking is not an isolated implementation oversight but a shared architectural assumption. The recovery path is uniformly treated as a trusted internal channel---a design choice inherited from classical exception-handling, where the failure payload is generated by the trusted computing base. In the LLM-agent setting, where failure payloads frequently embed external content, this assumption no longer holds, yet no framework in our sample has revised it.

\paragraph{Four of six frameworks exhibit the trampoline signature.}
Reflexion, MetaGPT, Aider, and AutoGen all satisfy Q1=No (no provenance tag) and Q2=Yes (high-trust frame). In each case, externally originated content embedded in a failure payload is re-injected into the LLM context under a frame that signals trustworthiness:

\begin{itemize}[leftmargin=*]
    \item \textbf{Reflexion} wraps the test-runner output in a ``[unit test results from previous impl]'' envelope under a system prompt that frames the conversation as a recovery session. The LLM is instructed to use the feedback to improve its implementation, signaling that the content is authoritative diagnostic signal.
    \item \textbf{MetaGPT} prepends a role-playing instruction (``You are a Development Engineer or QA engineer'') that frames the entire payload---including the test stderr---as a message to act upon. The LLM is told to ``figure out your own role'' from the message, treating the stderr as part of the task description rather than untrusted diagnostic context.
    \item \textbf{Aider} embeds the file content in a \code{ValueError} whose message includes the directive ``Just reply with fixed versions of the blocks above.'' The edit-instruction frame signals that the content is a legitimate edit request, not adversarial input.
    \item \textbf{AutoGen} returns tool exceptions in the same \code{tool} message role used for successful results. The message role is the trust signal: the LLM has no way to distinguish a legitimate tool return from an error that embeds external content, because both arrive in the same role.
\end{itemize}

This combination---no provenance tag plus high-trust framing---is the structural signature of the trust-escalation trampoline: content that should be treated as untrusted (because it may originate from external sources) is instead treated as trusted (because the recovery path wraps it in a high-trust frame without checking its origin).

\paragraph{LangGraph: partial trampoline.}
LangGraph provides partial provenance tagging at the message level (\code{ToolMessage} with \code{status="error"} for exceptions), but does not apply a high-trust frame to error content. The provenance gap exists for returned error strings (which receive \code{status="success"}), but the trust-escalation step (high-trust framing) is absent. We classify LangGraph as \emph{partial trampoline}: the structural preconditions for the attack are present (no content-level trust distinction), but the active trust-upgrade step is missing. Whether the partial signature is exploitable in practice is examined in RQ2 (\S\ref{sec:langgraph-validation}).

\paragraph{OpenHands: no trampoline.}
OpenHands wraps tool exceptions in \code{ErrorObservation} objects and manages them through state history rather than prompt-level framing. While the provenance gap exists (errors and successful observations are converted by the same path), the trust-escalation step is weaker: no system-level frame is applied to the error content. We classify OpenHands as \emph{no trampoline}. This does not mean OpenHands is immune to recovery-channel attacks---the provenance gap still allows error content to enter the LLM context without a trust downgrade---but the specific trust-escalation mechanism studied in this paper is absent.

\paragraph{Cross-case observation: maturity independence.}
The trampoline signature is not correlated with framework maturity or adoption. It appears in both small frameworks (Reflexion, 2.4k stars) and large ones (AutoGen, 35k stars; MetaGPT, 40k stars). It appears in single-agent retry systems (Reflexion, Aider) and multi-agent collaboration platforms (MetaGPT, AutoGen). It appears in graph-based orchestration (LangGraph, partially) and state-managed architectures (OpenHands, absent). This suggests the provenance gap is a \emph{systemic} design pattern in the LLM agent ecosystem, not an artifact of any single framework's implementation choices. The convergence is consistent with a shared intellectual lineage: all six frameworks inherit the assumption---from the self-healing and reflexion literature~\cite{reflexion,self-refine,critic}---that the recovery path is a corrective loop operating on benign diagnostic content.

\paragraph{RQ1 summary.}
The structural code analysis reveals that the trust-escalation trampoline signature is prevalent across the production agent ecosystem: four of six frameworks exhibit the full signature (no provenance tag $\wedge$ high-trust frame), one exhibits a partial signature, and only one lacks the trampoline entirely. The prevalence is not explained by framework size, adoption, or architectural style, indicating a systemic design blind spot in the self-healing pattern. Whether this structural signature translates to practical exploitability is the subject of RQ2.
