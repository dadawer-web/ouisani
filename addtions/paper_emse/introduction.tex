\section{Introduction}
\label{sec:introduction}

\paragraph{Background.}
Large language model (LLM) agents are increasingly deployed with \emph{self-healing} mechanisms---automated recovery pipelines that capture execution failures and re-inject diagnostic context into subsequent iterations~\cite{reflexion,autogen,swe-agent}. When an agent fails (empty response, tool error, verification failure, or semantic crash), a recovery orchestrator classifies the fault and dispatches a recovery strategy: re-injection of error context into the next prompt, model fallback, or human escalation. This architectural pattern is motivated by the empirical observation that LLM agents fail often, and that retrying with structured diagnostic context frequently succeeds where the original attempt did not~\cite{self-refine,critic}. As a result, self-healing has become a load-bearing component of production agent frameworks, with frameworks such as Reflexion~\cite{reflexion}, MetaGPT~\cite{meta-agent}, Aider~\cite{aider-code}, OpenHands~\cite{openhands-code}, AutoGen~\cite{autogen}, and LangGraph~\cite{langgraph} all shipping retry, reflection, or debug loops as core functionality.

\paragraph{Problem.}
Despite the richness of this recovery machinery, the trust assumptions embedded in the recovery path have not been systematically examined from a software engineering perspective. The recovery pipeline inherits an implicit assumption from classical exception handling: \emph{that failure is a benign accident and that retry is safe.} This assumption holds in classical systems because exception payloads are generated by the trusted computing base. It does not hold in LLM agent systems, where the failure payload is frequently \emph{external content that the agent was processing when it crashed}---e.g., a fetched web page, a test case output, or a file read from disk. An agent that fetches adversarial content, throws an exception whose trace embeds that content, and hands the trace to the recovery pipeline is effectively delivering attacker-influenced content to a path that was never designed to receive untrusted input. We call this attack class \emph{\rci{}}: prompt injection delivered \emph{through} the failure payload, \emph{on} the recovery path, bypassing the forward execution path that the prompt-injection literature has studied. The security literature has studied prompt injection on the \emph{forward} execution path~\cite{greshake2023indirect,liu2024formalizing}, but the \emph{reverse} recovery path---from failure, through diagnostic logging, back into the next-round LLM context---has remained an unexamined trust boundary in the empirical software engineering literature.

\paragraph{Research Questions.}
This paper investigates the prevalence, exploitability, and defendability of trust-assumption gaps in self-healing LLM agent frameworks through a coordinated empirical study spanning source-level code analysis, controlled and end-to-end attack measurement, and defense-effectiveness evaluation. We ask three research questions:

\begin{description}[leftmargin=*]
    \item[\textbf{RQ1} (Prevalence).] How prevalent is the \emph{trust-escalation trampoline} signature---a recovery path that re-injects untagged failure content under a high-trust frame---across production-grade self-healing LLM agent frameworks? We answer this through source-level code analysis of six frameworks and construct a recovery-path provenance taxonomy using grounded-theory coding (\S\ref{sec:results}).
    \item[\textbf{RQ2} (Exploitability and Severity).] Is the structural signature practically exploitable as a recovery-channel prompt-injection vector, and how severe is the resulting attack? We answer this through three complementary experiments that escalate from a controlled testbed (\S\ref{sec:recova-testbed}) to cross-framework validation on LangGraph (\S\ref{sec:langgraph-validation}) and a confirmed end-to-end exploit on Reflexion's shipped retry path (\S\ref{sec:reflexion-e2e}), together with a forward-defense bypass establishing \rci{} as an independent attack surface (\S\ref{sec:forward-bypass}).
    \item[\textbf{RQ3} (Defense Effectiveness).] How effective is the content-level \trustorigin{} provenance-tagging defense, and under what conditions does it degrade? We answer this through a naive-baseline comparison (\S\ref{sec:naive-baseline}), a cross-model generalization study (\S\ref{sec:cross-model}), a defense-aware attacker experiment (\S\ref{sec:defense-aware}), and a defense-cost analysis (\S\ref{sec:defense-cost}).
\end{description}

\paragraph{Contributions.}
This paper makes the following contributions to empirical software engineering:

\begin{itemize}[leftmargin=*]
    \item \textbf{A recovery-pattern taxonomy and cross-case classification (RQ1).} We construct a taxonomy of how self-healing LLM agent frameworks handle failure-content provenance, using grounded theory coding (open, axial, selective) over the source code of six production frameworks (Reflexion, MetaGPT, Aider, OpenHands, AutoGen, LangGraph; combined $\sim$105k+ GitHub stars) at fixed commit hashes. We find that five of six frameworks exhibit no provenance tracking, and four of six exhibit the full trust-escalation trampoline signature (no provenance tag \emph{and} high-trust framing).

    \item \textbf{A multi-layered exploitability and severity evaluation (RQ2).} We empirically establish that the trampoline signature is practically exploitable through three complementary experiments: (i)~a controlled testbed experiment on \system{}~\cite{omo} using real LLM APIs (DeepSeek-V4-Flash, Qwen2.5-72B-Instruct) over 500 trials, yielding a baseline ASR of 0.57 (recovery-channel prompt injection via untagged failure content); (ii)~cross-framework validation on LangGraph's public API (recovery-path ASR 0.76, real agentic-loop ASR 0.96); and (iii)~a confirmed end-to-end exploit on Reflexion's actual shipped retry path (commit \texttt{218cf0e}) achieving ASR 0.52 ($p = 3.5 \times 10^{-10}$ vs.\ benign control). A forward-defense bypass experiment further shows \rci{} succeeds at ASR 0.68 even when three forward-path defenses are fully enabled ($p = 0.660$, indistinguishable from undefended), establishing \rci{} as an attack surface independent of forward-path injection.

    \item \textbf{A defense-effectiveness evaluation with cross-model and adaptive-attacker generalization (RQ3).} We evaluate the content-level \trustorigin{} provenance-tagging defense along four axes: (i)~against three naive baselines transplanted to the recovery channel (best naive baseline ASR 0.08, rising to 0.42 under paraphrased variants; our defense 0.07); (ii)~across models of increasing instruction-following strength (defended ASR rises from 0.07 on DeepSeek/Qwen to 0.50 on gpt-oss-120b and 0.36 on a closed-weight frontier model, $p = 0.027$); (iii)~against a defense-aware attacker (ASR rises from 0.07 to 0.15, preserving 84\% relative reduction); and (iv)~under defense-cost analysis (0\% false alarms, sub-millisecond machinery overhead). The central empirical finding is that content-level provenance defenses are effective but probabilistic, and degrade predictably as models become stronger instruction-followers---quantifying the ceiling of content-level mitigation on the recovery channel.

    \item \textbf{Statistical rigor throughout.} All attack-success-rate measurements report Wilson 95\% confidence intervals for the binomial proportion; pairwise comparisons use Fisher's exact test with Bonferroni correction where applicable; the attack-success classifier is validated against two human annotators with Cohen's $\kappa \geq 0.88$ (``almost perfect'' agreement). Raw trial logs, annotation rubrics, and analysis scripts are released as a replication package.
\end{itemize}

\paragraph{Scope.}
This paper is an empirical software engineering study of a single attack class (\rci{} via untagged failure content on the recovery path). It does not study privilege-escalation vectors on the recovery path, role-replacement primitives, or topology-mutation surfaces, which are distinct authorization problems outside the scope of this empirical study. The defense evaluated here is a content-level provenance defense; structural or authorization-based defenses are likewise outside the scope of this paper. The empirical scope is six production frameworks at fixed commits, three open-weights LLMs and one closed-weight model, and a single-round defense-aware attacker.
